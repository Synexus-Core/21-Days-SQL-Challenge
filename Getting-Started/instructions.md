# 🗺️ Instructions: How to Execute This Challenge

Welcome to the 21-Day SQL Challenge by Synexus. This is not a tutorial on how to use an ORM (Object-Relational Mapper) to let a framework write your database queries for you. This is a deep dive into the raw data layer. 

To succeed, you must understand how data is stored, related, and retrieved at the lowest level.

## 1. The Core Philosophy
**Standard, not a trend. The logic, not a language.** 
Frameworks and backend languages change, but relational databases and SQL have powered the enterprise web for decades. If you understand how to structure and query raw data efficiently, you can build systems in any language.

## 2. Setting Up Your Environment
For this challenge, we will write pure, standard SQL. You will need a local database environment.
1. Download and install **MySQL Community Server**.
2. Download and install **MySQL Workbench** (the visual interface we will use to write and execute our queries).
3. Connect Workbench to your local server (usually `localhost` on port `3306` with the `root` password you set during installation).

## 3. The Daily Workflow
1. Create a public GitHub repository named `21-Days-SQL-Challenge`.
2. Every day, a new task folder (e.g., `Day-01`) will be published.
3. Read the `README.md` for the daily requirements and schema context.
4. Write your SQL queries in MySQL Workbench and test them to ensure they execute successfully.
5. Save your queries into a `.sql` file (e.g., `day01_schema.sql`).
6. Push your `.sql` file and a short personal `README.md` explaining your learnings to your GitHub repository.

## 4. Using AI Effectively
Do not ask AI to "Write the query to solve Day 4." You will learn nothing. 
Instead, use AI to explain concepts: *"Explain the difference between an INNER JOIN and a LEFT JOIN using a simple analogy of a school classroom."* Understand the theory, then write the query yourself.
